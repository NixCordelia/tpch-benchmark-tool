# TPC-H 双库对比报告

## 测试环境说明

- 报告生成时间：2026-08-19 01:19:47
- 配置文件：`config.compare.yaml`
- baseline：PostgreSQL 15（`localhost:5432` / `tpch`）
- target：MatrixDB 4.8.12-community Docker demo（`localhost:5433` / `mxadmin` / `tpch`）
- 数据：同一套 TPC-H SF=1，由 `scripts/copy_tpch_to_ymatrix.py` 从 PostgreSQL COPY 到 YMatrix；两边均有 `idx_lineitem_combo`
- 参数：`rounds=1`，`concurrency=1`，`warmup=false`，`timeout=300s`
- 对比 Query 数量：22（其中 Q21 仅 target 成功，不进入 avg 对比）

这是**独立的一轮对比实验**，不能和此前 PostgreSQL 3 轮 + 不限时补测（见 `results/pg_multirun_report.md`）混成同一张基线。例如本轮 PostgreSQL Q17 = 2569.46 ms，补测 Q17 = 2887899.71 ms，条件不同（串行 / 超时 / 缓存），禁止直接当「变快了 1000 倍」宣传。

## 对比汇总

- 可对比 Query 数量：21（两侧都有成功 `avg_ms`）

## 性能差异分析

### 最大性能回退（target 更慢）

- Query `12`：baseline 1558.61 ms，target 6374.13 ms，回退 4815.52 ms（308.96%）

### 最大性能提升（target 更快）

- Query `2`：baseline 125865.28 ms，target 4032.50 ms，变化 -121832.78 ms（-96.80%）

### 重点关注（target 更慢 Top 3）

- Query `12`：慢 4815.52 ms（308.96%）
- Query `6`：慢 4470.72 ms（448.62%）
- Query `17`：慢 2583.63 ms（100.55%）

### Q21

PostgreSQL 在 300s 超时（记录 301163.63 ms，`TIMEOUT`）。MatrixDB 在 6414.01 ms 完成。这说明在**本轮超时策略下** target 能跑完而 baseline 不能，但不能把「300s vs 6.4s」写成加速比（baseline 没有成功耗时）。

## 测试限制说明

- target 是 MatrixDB 4.8.12 Docker 试用镜像，不是 Windows 上安装的 5.2.1 社区版 rpm/deb
- 单轮、串行、timeout=300，不是官方 TPC-H 审计口径
- 11 快 / 10 慢，不能下「YMatrix 全面更快」的结论
- PostgreSQL 与 YMatrix 的执行器、分布键、JIT/优化器不同；Q6/Q12/Q15 等 target 更慢需要单独 EXPLAIN，本次未展开
